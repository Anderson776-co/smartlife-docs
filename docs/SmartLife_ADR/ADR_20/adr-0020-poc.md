# Prueba de Concepto — ADR-0020

## Objetivo

Validar que PostgreSQL sostiene operaciones DML y DDL básicas de forma correcta, y que mantiene un rendimiento adecuado en consultas de contención sobre un dataset de gran volumen (50.000 registros) gracias al uso de índices nativos (GIN) sobre columnas JSONB.

## Métricas y resultados

Se creó la tabla incidentes con una columna metadatos de tipo JSONB, y se pobló con 50.000 registros simulados mediante generate_series, combinando aleatoriamente valores de categoría, urgencia y torre. Se creó un índice GIN (idx_metadatos_gin) sobre la columna metadatos. Al ejecutar una consulta de contención (EXPLAIN ANALYZE SELECT COUNT(*) FROM incidentes WHERE metadatos @> '{"categoria": "mantenimiento", "urgencia": "alta"}') desde la terminal psql, el motor utilizó un Bitmap Index Scan sobre el índice GIN en lugar de un recorrido secuencial completo de la tabla, localizando 4.187 registros coincidentes de los 50.000 totales en un Execution Time de 11.515 ms (Planning Time: 3.670 ms). Adicionalmente, se validó el ciclo completo de operaciones DDL y DML básicas sobre una tabla de prueba (prueba_ddl): CREATE TABLE se ejecutó exitosamente (confirmación "CREATE TABLE"), seguido de INSERT (confirmación "INSERT 0 1"), SELECT (retornando correctamente la fila insertada), UPDATE (confirmación "UPDATE 1"), DELETE (confirmación "DELETE 1") y finalmente DROP TABLE (confirmación "DROP TABLE") para limpiar el entorno de prueba.

## Conclusiones

La PoC valida dos criterios centrales de la decisión: primero, que PostgreSQL ejecuta correctamente el ciclo completo de operaciones DDL/DML fundamentales (crear estructura, insertar, consultar, actualizar, eliminar registros y eliminar estructura) sin errores; segundo, que el motor sostiene tiempos de respuesta bajos (11.515 ms) incluso sobre un dataset de 50.000 registros con datos semiestructurados (JSONB), gracias al uso efectivo del índice GIN, que evita un recorrido secuencial completo de la tabla,confirmado explícitamente en el plan de ejecución por el uso de "Bitmap Index Scan on idx_metadatos_gin" en lugar de un "Seq Scan". Este resultado respalda directamente el argumento del ADR sobre la capacidad de PostgreSQL para sostener los tiempos de respuesta exigidos por la matriz de transacciones bajo volúmenes de datos crecientes, como los proyectados para el módulo de incidentes y cuentas de cobro de SmartLife. Queda fuera del alcance de esta prueba medir el comportamiento bajo escritura concurrente (múltiples transacciones simultáneas) y validar el mecanismo de seguridad a nivel de fila (Row-Level Security), que podrían abordarse en una prueba complementaria si se considera necesario.
